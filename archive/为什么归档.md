# 归档说明

归档时间：2026-09-30
归档原因：传输拓扑需求变更——取消 PC 侧 WiFi AP / UDP/TCP 链路，改为
"PC —USB— C3主机 —(ESP-NOW多通道/有线)— C3从机"的集中转发拓扑，
帧格式改为"帧头+无线通道+设备ID+CMD+LEN+DATA+CRC"。
原 `backend/`、`frontend/`、`README.md` 基于旧拓扑（PC 开 AP、设备 TCP/UDP 连入），
整体归档，不再演进。

## 可复用资产（新框架设计时参考，参考后即可弃）

- `backend/app/protocol/frame.py`：流式帧解析器（同步字 + LEN + CRC16 丢弃误同步，坏帧重同步），
  有 8 个单测（`tests/test_frame.py`），"LEN 前缀式防误同步"思路已被验证
- `backend/app/links/base.py`：单一 RX Owner 帧分发模式（所有链路汇入一个同步入口）
- `backend/app/links/mock_link.py`：仿真设备走真实协议栈的 Mock 模式
- `backend/app/devices/manager.py`：心跳租约、按地址推断设备类型、帧环形缓冲
- `backend/app/services/`：遥测枢纽（10Hz 批推）、发次归档（目录 + manifest.json）
- `frontend/`：页面骨架、WS 重连客户端、双 Context 状态管理、协议调试页交互
- Windows 兼容结论：UdpLink 若保留需 Selector 事件循环；新拓扑若只有 USB 串口则无此问题
